# Native workbench validation — November 11, 2026

## Implemented behavior

Verify an authorized signed release ZIP against a separately provisioned raw 32-byte Ed25519 public key, product, target, explicit sequence floor and review clock. Or compare that candidate with an explicitly selected existing owned deployment and exact expected-current digest. The actual original verifier reauthenticates manifests, SPDX, every payload byte, expiry, trust and sequence; review reports added, removed, changed and unchanged inventory. Inspect eligibility and retained high-water scope, then export the exact saved report. Signing, deployment initialization, activation and rollback remain explicit original CLI operations.

The new Tk view composes the existing project engine with bounded descriptor-based file admission, owner-local SQLite history, immutable saved bundle hashes, search/detail/filter controls, no-overwrite export, explicit deletion confirmation, Help/Licenses and graceful retained-worker exit. Default data resides outside the source/install tree. CLI contracts and custom paths are preserved.

## Gates and evidence limits

The Windows CI lane builds the complete one-file program and repeats the actual executable consumer; it retains original source, coverage and independent native/security checks. No new artifact/cache uploads were added. Local build outputs, screenshots, source/native receipts and private paths remain ignored and outside public source. A hosted check is not claimed before it runs; old dated Office reports retain their original baseline.

Verification alone does not authenticate deployed state. Candidate comparison temporarily acquires the original owned deployment operation lock, revalidates active bytes and leaves the deployment pointer/history unchanged. GUI history is a separate SQLite transaction, not atomic with deployment state; review is not activation permission or malware certification. Operator/media aliases are assertions, not authentication or physical-transfer proof. Independent trust comes from outside the bundle. No signing-key picker, arbitrary payload execution, download or live deployment is exposed.

The profile guards prevent accidental linked-file writes to fixed mutable state before initialization. They do not turn a local single-OS-owner application into a hostile-administrator sandbox. Reports and aliases are not authenticated independent attestations. The portable executable is unsigned; no cross-platform native distribution, NSIS installation, universal safety or certification is asserted.
